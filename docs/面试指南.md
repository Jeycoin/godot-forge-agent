# GodotForge 面试指南

## 一、三分钟项目介绍

这是一个面向 Game Jam 快速原型场景的 AI 游戏开发 Agent。我想解决的不是“让模型写一段 GDScript”，而是生成结果能不能交付、能不能运行、失败后能不能修复。

用户输入自然语言需求后，系统先生成结构化 GameSpec 和包含文件所有权、公共接口的模块契约，再检索 Godot 4 文档。随后根据 plan.modules 通过 LangGraph 的 Send 并行启动 Gameplay、Scene 和 Interface 三个开发角色。集成时记录每个文件的 owner，确定性审查节点检查必需文件、契约冲突、模块越权、路径穿越和危险系统调用。

文件真正写入前会触发 interrupt，用户确认目标目录、模块契约、内容哈希和 unified diff 后才继续。工程写入采用临时文件替换，批处理失败会恢复原文件。随后先执行 Godot Import/解析检查，再运行项目内置的 smoke-test；每个阶段独立记录命令、日志、错误和耗时。失败时把真实日志交给修复节点，形成有上限的修复循环，状态通过 SQLite 持久化。

默认离线模型生成一个可玩的 2D 生存参考项目，保证没有 API Key 也能完整演示；真实模型通过同一套接口接入，安全与验证逻辑不变。

## 二、高频追问

### 1. 为什么选 Godot，不选 Unreal？

Godot 的 GDScript 和场景文件都是文本，方便 Agent 生成、审查和展示 diff；引擎开源轻量，Headless 验证成本低。Unreal 的 Blueprint 和 C++ 编译链路更重，适合有既有 Unreal 工程基础时再做。

### 2. 为什么这个项目需要 LangGraph？

流程包含动态并行、文件审批、运行验证和多轮修复，不是线性 Chain。LangGraph 将状态和控制流显式化，并能通过 checkpointer 在审批中断后恢复。

### 3. 多 Agent 会不会同时修改同一文件？

计划中的 ModuleContract 先声明 owned_paths 和 public_interfaces。集成后每个文件带有实际 owner，审查节点同时检查重复路径、契约冲突和模块越权；不合法就进入有界修复，而不是让后写结果覆盖先写结果。

### 4. 如何判断游戏生成成功？

不能只看模型回答，也不能只看进程退出码。项目要求固定命令真实启动 Godot，并在游戏脚本中检查玩家、敌人、HUD 和游戏循环，打印 SMOKE_TEST_OK 后主动退出。Agent 同时校验退出码和业务成功标记。

### 5. 自动修复会不会无限循环？

`repair_count` 由状态记录，最大次数由 Settings 限制。达到上限后保留工程和真实错误日志，转人工处理，不通过删除测试或忽略错误来制造成功。

### 6. 为什么审批后修复不需要再次审批？

首次授权限定了目标工作区和自动验证流程，后续修复只能修改同一批白名单文件。更严格的系统可以按 diff 大小或文件范围重新授权，这是后续安全演进方向。

### 7. 如何防止模型写入工作区之外？

所有路径统一为 PurePosixPath，拒绝绝对路径、反斜杠和 `..`，只允许 project.godot、README.md、scripts/*.gd、scenes/*.tscn；写入前再检查 resolve 后的目标仍位于工作区内。

### 8. 是否已经是完整代码安全沙箱？

不是。路径白名单和 OS.execute 检查只是基础防线，GDScript 还有其他系统能力。真实运行不可信代码需要容器或虚拟机隔离、资源限制、网络限制和更完整的策略。

### 9. RAG 在项目里有什么实际作用？

为模型提供 Godot 4 的工程结构、CharacterBody2D、CanvasLayer、信号和 Headless 协议，减少 Godot 3 与 Godot 4 API 混用。文档只作为参考，最终正确性仍由静态审查和真实运行验证。

### 10. 如何评估这个项目？

分别评估工程完成、审批门禁、文件完整和真实引擎验证，不用“回答看起来不错”替代运行结果。后续可加入首次运行通过率、平均修复次数、玩法断言通过率和生成延迟，但数字必须来自实际评估。

## 三、现场演示顺序

1. 运行 `godot-forge run ... --thread-id interview-demo`。
2. 展示三个并行 develop 轨迹和待审批文件清单，指出此时工程尚未写入。
3. 执行 `godot-forge resume interview-demo --approve`。
4. 展示真实 Godot 输出中的 `SMOKE_TEST_OK`。
5. 用 Godot 编辑器打开 `generated/game/project.godot` 并运行游戏。
6. 打开 `tests/test_workflow.py`，说明拒绝、修复和断点恢复测试。

## 四、学生身份话术

> 这是我在学习 LangGraph 和 Godot 时独立设计并实现的项目。我以 Game Jam 快速原型为场景，重点研究如何让 AI 生成代码形成可验证的工程闭环。默认模板用于离线复现，真实模型适配器、审批、持久化、测试和引擎验证均由项目代码实现。项目已用 DeepSeek 在线生成和 Godot 4.7.2 完成过一次真实全链路测试，但单次通过不代表任意需求都能成功，后续仍需要扩大评估集并完善沙箱隔离。

这种表达比“使用 Vibe Coding 做了一个游戏”更能体现需求分析、架构设计、工程实现和验证能力。
